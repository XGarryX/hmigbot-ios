# iOS 依赖到鸿蒙依赖

先读 ios-project-inspector 和 ios-api-inventory 的依赖清单与调用点。
确定依赖是源码、闭源 framework、C/C++ 引擎、系统服务还是远程协议。

1. 列出实际使用的 API 子集、数据模型、初始化、回调线程、错误与释放行为。
2. 先查厂商官方目标支持与版本，再查可信开源实现；记录来源、许可证、更新时间。
3. 对每项契约选择直接可用库、适配层、目标原生重写或 NAPI 方案。
4. C/C++ 源复用须核对平台调用、架构、编译链、ABI、内存所有权与线程边界。
   预编译 .xcframework 不能直接变为目标库。
5. 同名功能但行为变化进入 decision-ledger；未知源码/闭源行为以公开契约或测试补证。
6. 按计划在 feature-base 或所属 slice 实现接口、编译、契约测试和必要设备测试。

输出依赖替代矩阵及每条证据；只下载/导入依赖不算对应业务功能已完成。
源协议语义与目标依赖版本分别固定，避免后续更新悄悄改变基线。
