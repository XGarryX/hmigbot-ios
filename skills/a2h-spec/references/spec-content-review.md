# 规格内容复核

以原始源码和已批准决策核对规格，不仅看生成器自述或目标代码。逐功能走完真实入口、输入、状态/数据处理、副作用、错误/取消、持久恢复与反馈。无适用路径给具体理由，不发明补齐模板的逻辑。

| 检查 | 问题 |
|---|---|
| 范围 | 是否区分生产、Preview、测试、扩展及平台条件？共享文件是否按符号区分？ |
| 行为 | 输入、公式、分支、具体结果是什么？ |
| 状态 | 谁拥有真值，谁写谁读，重入/身份改变/离开如何处理？ |
| 接口 | 调用两侧类型、单位、nil、句柄、错误和线程是否一致？ |
| 接线 | 页面handler调用谁，反馈怎样回写，组件由谁承载？ |
| AC | 不看目标代码能否得出期望？是否混合不同行为或延迟展开断言？ |
| 证据 | 真值行是否实际发生该行为？是否误用import、注释、Preview？ |
| 消费 | Plan能否按对接点分任务，execute能否按目标锚点和源入口实施？ |

## 必测反例
- import CoreData 不证明保存或重载，需追到实际操作。
- Preview 内示例实体、固定宽度不能作产品初值或视觉验收。
- “对源赋值的边界输入观察结果”需改为实际输入、运算与期望。
- “其余20处原表达式见审阅”需展开可独立判断的断言。
- 公共目标接口不能推给 plan 临场定义；plan 负责施工分配。
- reviewed 字段和哈希齐全不能独自证明语义正确。

## 实际检查与交接
先 spec-check 修正内容，再 source-check --harness 检查内容、原生信号/覆盖与专业资料；继续原 addenda、差异、追踪及计划覆盖检查。保留命令、退出码和报告路径。

Gate C 披露 source digest、统一覆盖分母、检查范围和未决/未运行项。内容、源合同、目标编译、行为分别记状态，不能由本检查表宣称 App 已验收。
