# Neutral host evaluations (THEF-16)

These are three small, independently authored logic candidates and fixed host
oracles for Binding/navigation state, UIKit event/resource logic, and async
cancellation/persistence/errors. They are evaluation fixtures, not a converted
application. The accepted upstream commits are `0b95a1d` and `d7cdf22`.

Select existing runtimes explicitly; nothing installs or downloads dependencies:

```powershell
python -X utf8 evaluations/wb-0.9.1/neutral/neutral_baselines.py --node '<node.exe>' --typescript '<typescript.js>' --output '<new-output-directory>'
python -X utf8 evaluations/wb-0.9.1/neutral/neutral_consume.py --node '<node.exe>' --typescript '<typescript.js>' --output '<new-consumer-output-directory>'
```

`HMIGBOT_NEUTRAL_NODE` and `HMIGBOT_NEUTRAL_TYPESCRIPT` can supply the same options.
Node may also come from PATH. The original remote runtime locations remain last
fallbacks for compatibility; missing files produce an actionable error. Every
case command generated by `neutral_consume.py` records and passes the selected
Node executable to `neutral_case_runner.py`. Reports record runtime versions and
file hashes. Select a fresh output directory; the consumer recreates only its
own `project` subdirectory, with a link/escape check before cleanup.

Use `--candidate binding-navigation '<candidate.ets>'` on either command to make
an alternative artifact the formal input. The known counterexample replaces
`this.enabled = false;` inside `disable()` with `/* dropped */`; the authored
normal candidate is not modified. Unknown/duplicate sample overrides are rejected.
Failed baseline runs exit 1; failed real behavior-gate runs preserve its exit 2.
Reports are still retained on those expected negative runs.

The normal host denominator is **6 business cases**, separate from **6 guard
cases**. Guard success means mutation discrimination, never business acceptance.
The broken disable candidate must fail business BN-AC02 and guard BN-AC04. The
current behavior gate may also reject its empty anchored `disable` handler.

`neutral_consume.py` uses the real `behavior.verify` process-observation API over
explicit host cases and a minimal hand-authored source fact graph. Its host PASS
and `behavior_verified` apply only to those supplied cases. HarmonyOS compilation,
ArkUI rendering/navigation, iOS compilation/execution, device behavior, visual
fidelity, and a complete `ios_harness` source-analysis refresh are **UNVERIFIED**.
The copied behavior cases use the host `unit` runner; this does not satisfy the
device/UI/async judgments in the independent AC matrix. Neither a host PASS nor
guard success establishes App migration success or a 100% product claim.
