# 真实规则生成对照与返修记录

本样本用于检查工具规则能否被模型实际消费。它只覆盖一个SwiftUI源片段、功能MD、页面MD和meta三份产物，不是完整迁移工程或完整Plan验收。

源为[source/Counter.swift](source/Counter.swift)。旧组实际按提交`b22205f`规则生成；新组按施工中的profile 2规则生成，run记录实际读取文件与摘要。新组所有17份规则的生成时字节已保存为精确快照（含从变更逆向恢复且SHA256完全匹配的schema），不能用最终工具文件冒充当时版本。旧组作者此前参与过新规则施工，记录已披露，因此这不是盲测。

| 组 | 记录与产物 | 实际状态 |
|---|---|---|
| old | [run.json](old/run.json)、其下三份Spec | 原规则生成；按原profile解释，不套用新版表头作为失败原因 |
| new | [run.json](new/run.json)、其下三份Spec | 首轮原样保留；存在目标锚点和最终schema字段布局失败 |
| new-round2 | [run.json](new-round2/run.json)及三份重新生成产物 | 按反馈第二次生成，局部格式与独立源复核通过；不替换首轮失败证据 |

## 独立源复核

复核者`/root/final_contract_review`与两个生成实例分离；复核时未写样本。基准源码行：初态4–6、Add7、Save同步段9–12、等待/取消检查14–15、set→Saved16–17、错误18–19、Cancel请求22、StateObject26、树与布局28–35、Preview39。

| 检查类别 | old 与 new 的实际内容 | 结论 |
|---|---|---|
| 初态/恢复 | 两组均为0/Ready，均明确没有读取savedCount恢复 | 本例语义均保留，不能由表头推断 |
| Add/数值 | 均+1且不改message；均披露极值/数值域未核验 | 无运行证据证明Int映射 |
| 提交/完成 | 均区分Saving、同步返回、等待结束与Saved | 无证据支持本例时序语义提升 |
| 捕获快照 | 均保留Save入口2、等待中Add至3、最终保存2 | 仍需可控调度验证 |
| 取消与重入 | 均区分取消请求与catch完成；均保留旧任务catch可回写共享message | 不能擅加latest-wins或立即取消反馈 |
| 存储/错误 | 均为set后Saved、set不等于磁盘flush，普通错误为Failed | 未验证平台存储API或设备 |
| 状态/生命周期 | 均单一StateObject、不因body重算重建、无额外离页取消 | 宿主身份未知 |
| 组件/布局/资源 | 新组逐节点固定表和目标资源ID更细；两组均保留16间距/20padding且不猜固定尺寸 | 结构便于检查/消费，未转换资源或证明视觉一致 |
| 动作与接线 | 新组定义三动作ID并以action-use消费；两组本例时序均正确 | 新协议增加可机械核对的唯一定义/引用关系 |
| AC目标 | 新组F001-AC10使用裸`CounterPage`，未声明Owner.symbol | 当前目标合同解析实际可检出TARGET_UNDEFINED，首轮不得宣称通过 |
| meta格式 | 新组按生成时较宽schema添加三个自定义顶层字段；最终schema禁止 | 最终工具实际拒绝，需按extensions协议重新生成；记录版本差 |
| 呈现与范围 | 两组均披露宿主未知；meta却各给候选类型。Preview不作为产品初态 | 候选不能当确认入口；无完整机器排除账本，不能宣称source gate通过 |

独立复核没有发现“新组修复旧组关键时序错误”的证据；AC数量也不等于行为覆盖率。可以确认新规程生成了更明确的结构和动作引用，且真实生成仍会犯错误，必须经过检查、原作者返修和独立复查。不得从本例宣称语义正确率或真实项目成功率提高某个百分比。

## 工具反馈后的修正

保留`new/`原样。工具模板随后补清UI验收的已声明Owner.symbol锚点、meta领域扩展放extensions、宿主未确认时省略可选page_type。第二轮由原生成实例重新读源和最新规则生成，保存新的读取快照与摘要。格式自检只覆盖这三份文件，缺少的common/facts/semantics/coverage、独立SDK核验及宿主事实继续是全套门禁的阻塞，不能补造伴随件使其假通过。

本样本未执行源编译、目标编译、设备、视觉或完整harness；工具自动化回归与安装证据另见[验证说明](../../../docs/VALIDATION.md)。

第二轮独立复核及实际定点检查见[review.json](review.json)：源、17份规则快照与3份输出摘要一致；meta与6个动作块schema通过；AC目标均已声明。直接产物检查只报缺失本次未生成的5份公共MD，三份样本没有局部finding。上述结果不能绕过缺失机器伴随件、宿主和目标API等阻塞。run.json保留生成时`pending_external_reviewer`原记录，独立结果在后生成的review.json中记录。
