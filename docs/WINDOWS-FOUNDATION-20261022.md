## 最小目标与验收合同

- 规模：第一方产品代码行与物理行、测试、生成/第三方代码分别展示；固定源 SHA、真实构建范围及统计工具。真实100k/200k工程与合成容量夹具分账。Cuike约2109物理代码行，只是小型真实闭环。
- 质量：源独立审定的页面×状态×必要环境矩阵和业务AC是分母。未知、未支持、未测继续登记；批准替代与源等价分开。机器facts或局部PASS不能自己证明完整分母。
- 时间：完整必要准备到最后一次当前构建、修复及全部必验视觉/业务验证结束，计入排队、等待和失败重试。冷环境/已备环境分开展示。完整必验矩阵在同一7200秒挑战内，抽样不能替代双100%。
- 用量：所有实际调用的总input（含cache）+总output，按唯一call-id与attempt核对；子集不重复，遗漏保持UNKNOWN。全调用严格<20M，运行额度可更低。账本不自动发现宿主未上报的调用。
- 在途接口：同一run/project内，在模型调用前用唯一call-id预留保守上界；锁内检查已用+所有未结算预留+新额度。真实usage结算同一ID，未知usage不能释放成已知零，实际超额也必须保留。预测和预留不计作实际消耗。
- 终局接口：完整完成报告必须消费当前源/目标/包/规格/环境绑定的真实构建、逐状态视觉和业务结果，缺项拒绝双100%。本轮仅冻结此合同，**尚未实现完整终局profile及双端证据汇合**，现有可选verify仍按原语义工作。

## 不变的安全边界

去重只在一次step输入边界内生效，不以mtime/size复用，不跨命令继承PASS，不替代全图/基线/最终当前证据校验。调用者仍应遵守冻结输入不可并发修改的合同。

host_profile是当前发现和候选选择，未自动配置或执行Xcode。SwiftSyntax成功不自动解除提取不完整问题，不自动变成编译绑定。provider执行仍需显式配置；源语义硬门保留。

预留由调用宿主显式使用，不自动预测token、不发现遗漏调用、不终止正在运行的请求。`next-batch`仍是显式账本守卫，不自动为返回任务分配call-id/额度。先取得批次，再为实际模型调用预留；预留耗尽后普通next-batch检查会拒绝更多工作，但已成功取得预留的调用由宿主按该许可执行。回收结果不因额度超限而禁止。

Mac启动身份的计时证明、完整宿主调用对账、原生解析/绑定及真实App双端验证属于后续工作，不能把本轮工具回归当成它们已完成。
